# 개인 영어 학습 서비스의 요구사항

2026-10-26 강PD는 개인 학습부터 완성하고, 지금의 영어 감각·책 장면 학습을 다루기로 정했다.
아래 여섯 관계를 모델과 서비스 구성의 기준으로 사용하도록 승인했다. 이후 웹앱 제작 모델의 대상을 다시 정하면서,
이 내용은 제품 요구사항으로 구분했다. 학습 내용의 정본은 study-and-learn 프로젝트다.

## 승인된 약속

| 약속 | 서비스가 지킬 것 |
| --- | --- |
| 장면에서 표현을 고른다 | 문제에 맥락을 함께 보이고 장면을 표현 선택의 기준으로 삼는다 |
| 수행의 차이를 남긴다 | 정답 여부와 함께 처음 답, 선택한 까닭, 힌트, 스스로 고친 답과 질답을 구분해 남긴다 |
| 먼저 떠올리고 푼다 | 답을 제출한 뒤 피드백과 추가 질문을 이어 간다 |
| 실제 막힌 곳을 다시 꺼낸다 | 지난 풀이를 복습의 재료로 삼고 다음 유닛은 기존 로드맵을 따른다 |
| 멈춘 맥락에서 이어 한다 | 문제 도중 나가도 진행 상태와 풀이 맥락을 복원한다. 편리함은 사용 뒤 확인한다 |
| AI와 실제 수행을 구분한다 | AI의 판단을 학습 완료나 확정된 배움으로 자동 기록하지 않는다 |

## 현재 구현과 남은 일

기존 공개 콘텐츠, 장면 퀴즈와 문장 해설기를 Next.js·Cloudflare로 이관한 전환본이 있다.
개인 학습의 기록 저장·이어 하기·질답을 포함한 새 학습 흐름은 아직 구현하지 않았다.
기록의 저장 위치와 인증, 기존 파일 기록과의 연결은 구체적인 작업 계약에서 정한다.
아직 정하지 않은 숙달 점수, 복습 간격과 학습 완료 판정을 임의로 도입하지 않는다.

2026-10-26 강PD는 UX 설계 모델을 준비하고 앱 디자인을 처음부터 다시 하도록 지시했다.
정보구조·흐름·시각 체계의 첫 제안은 `docs/ux-design.md`, 시안과 검증 범위는 `docs/tasks/ux-redesign.md`에 있다.
디자인 시안의 브라우저 임시 기록은 실제 개인 학습 저장·인증의 구현이나 study-and-learn 기록을 대신하지 않는다.

이어서 강PD는 적절한 이미지와 터미널처럼 이어지는 AI 대화를 요구하며 소개 중심 화면의 한계를 지적했다.
앱의 기본 화면은 현재 장면·내 수행·AI 대화가 이어지는 학습 작업 공간으로 만든다. AI는 보낸 질문과 제출한 답·수정·
이전 질답을 같은 문제의 맥락으로 사용한다. 미전송 초안을 자동 제출하거나 AI의 설명을 강PD의 배움으로 확정하지 않는다.
이미지는 장면 재구성과 감각 도식의 역할을 구별한다. 적용 범위와 한계는 `docs/tasks/learning-workspace.md`에 있다.

제작 판단은 `knowledge/domain/web-app-production.md`, 구조 판단은 `knowledge/domain/web-app-architecture.md`,
Next.js 구현 판단은 `knowledge/domain/nextjs-development.md`를 따른다. 이 문서의 약속을 고칠 때는 강PD와 합의한다.
