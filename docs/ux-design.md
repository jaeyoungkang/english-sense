# 목차가 생기는 학습 문서

이 문서는 강PD가 승인한 문서형 본문·감각 자료 스택·누적 대화의 디자인이다.
실제 구현·수용 근거·모델 판단은 `docs/tasks/document-workspace.md`, 원칙은 `knowledge/domain/web-app-ux-design.md`가 소유한다.

## 읽는 문서, 이어지는 대화

본문은 제목·절·문단·출처·풀이와 AI 대화를 가진 한 권의 학습 문서다. 감각 자료와 퀴즈를 추가하면 목차가 만들어진다.
퀴즈마다 처음 답·수정을 구분하고 질문과 AI 응답은 발생 순서대로 이어진다. 흰 문서 면, 넉넉한 읽기 폭과 간격,
뚜렷한 절 번호와 가는 구분선으로 구조를 보인다. 대화의 화자·대상은 작은 머리표와 여백으로 구분한다.

## 화면의 구성

- 데스크톱 왼쪽: 문서 제목과 실제 추가된 자료·열린 퀴즈의 목차. 누르면 해당 본문 위치를 읽는다.
- 본문 위 고정: 감각 자료 스택. 최신 추가 자료가 위에 있고 하나를 펼치면 나머지는 제목만 남는다.
- 가운데: 자료 본문, 장면과 퀴즈, 최초 답·수정·질답이 이어지는 학습 문서.
- 아래 고정: 현재 AI 질문 대상과 입력. 읽는 자료와 다르면 구분해 표시한다.
- 모바일: 목차를 명시적으로 열고 이동하면 본문으로 돌아온다. 스택 높이를 제한해 대화·입력을 유지한다.

자료를 다시 펼쳐도 본문이나 목차 순서는 바뀌지 않는다. 목차 이동과 자료 열람만으로 AI 질문 대상은 바뀌지 않는다.
퀴즈의 ‘이 퀴즈에 질문하기’를 선택할 때 질문 대상을 바꾸며 대상별 초안을 유지한다.

## 실제 항목에서 생기는 목차

처음에는 have 감각 자료와 첫 퀴즈가 있다. 다음 퀴즈를 추가하면 그 항목이, get 같은 자료를 추가하면 그 자료가
본문과 목차에 함께 생긴다. 아직 열지 않은 퀴즈나 준비되지 않은 학습 유닛을 완료·진도처럼 표시하지 않는다.
자료·카드·본문 앵커에 같은 식별을 사용하며 독립적으로 만든 메뉴 목록을 학습 기록처럼 관리하지 않는다.
본문에서는 자료와 수행을 다시 읽고, 목차에서는 해당 위치를 빠르게 찾는다.

## 상단 자료 스택

have 뒤 get을 추가하면 get이 위에서 펼쳐지고 have는 제목만 남는다. have를 다시 펼치면 get은 접히고
have 그림·핵심 설명이 나타난다. 문서 본문은 have를 읽고 get을 추가한 순서를 그대로 유지한다.

have의 도해는 기존 그림과 ‘내 영역 안에 놓여 있다. 물건뿐 아니라 몸·마음·시간·할 일·지난 일도 내 영역이 됩니다’라는
본문을 함께 쓴다. get·be·go는 기존 공개 감각 설명·예시와 관계 도식을 사용한다. 감각 자료 추가는 새 퀴즈 출제나 학습 완료가 아니다.

## 유지하는 학습과 복원

현재 대화형 퀴즈는 기존 have 일곱 문항이다. 선택형·쓰기형·최초 답·수정·관련 질답과 실제 순서를 보존한다.
취소·실패·재시도·늦은 응답 배제·읽기 위치 유지·v1/v2 읽기 전용 이관과 v3 임시 복원을 유지한다.
자료 스택과 목차의 UI 상태는 학습 기록과 별도 보관한다. UI 상태가 깨져도 기존 학습을 초기화하지 않는다.
공개 자료 판이 바뀐 기록과 현재 AI 요청의 경계는 기존 계약을 따른다.

제출 전 대화는 무료 준비 안내, 제출 뒤는 실제 AI다. 서버 DB·계정·다른 기기 동기화·come 학습 개방은 아직 없다.
이 설계가 더 편리한지는 강PD가 실제로 사용한 뒤 판단한다.
