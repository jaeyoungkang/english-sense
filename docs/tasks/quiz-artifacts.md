# 대화에 쌓는 퀴즈 아티팩트

## 승인과 기대

2026-10-26 강PD는 기존 AI 대화형 인터페이스를 참고해 퀴즈 아티팩트를 쌓도록 제안했고,
모델을 먼저 갱신한 뒤 작업하며 실제 테스트로 모델의 유효성을 판단하도록 승인했다.
UX 모델 관계 12~15와 구조 모델 관계 16·규칙 13을 배경으로 삼는다.

표현 감각 자료는 상단에 두고, 기존 have 책 장면의 일곱 문항(고르기 다섯·쓰기 둘)을 독립 카드로 추가한다.
이것은 기존 학습 자료를 잇는 일이며 새로운 로드맵 유닛·복습 간격·숙달 판정을 정하는 일이 아니다.
카드마다 장면·문제·선택지 또는 쓰기 입력·최초 답·수정을 유지하고, 관련 AI 대화의 대상을 명시한다.
다음 문항은 사용자가 추가한다. AI의 일반 텍스트를 실행하거나 출제 명령으로 해석하지 않는다.

## 실행 계약과 소유권

영향은 reshape다. 현재 단일 문제의 상태와 API를 문항·아티팩트별로 구분한다.

- 서버 문항 목록은 기존 정본 일곱 문제를 명시적 ID로 조회한다. 공개 props에는 출처·자료 판·장면·발문·유형·선택지 문장만 넣는다.
- 정답 분류·이유·해설·모범 답·교정 예시는 서버에서 조회한다. 서버는 요청 대상의 정본만 AI 맥락에 넣는다.
- 새 요청은 수업·문항·자료 판·아티팩트·요청 ID, 최초 답·수정·해당 대화·새 질문을 가진다.
- 선택형과 쓰기형 최초 답을 구분하며 서버가 문항 유형과 입력을 대조한다. 기존 첫 문제 요청은 별도 호환 경로로 유지한다.
- 응답은 요청 ID와 대상 식별을 돌려준다. 화면의 현재 선택으로 응답 대상을 바꾸지 않는다.
- 브라우저는 문항별 상태와 전체 대화 사건 순서를 나누고, 카드 추가·제출·수정·요청·응답 순서를 보존한다.
- v1/v2는 기존 배포의 첫 문제에만 이관한다. 당시 기준을 확정할 수 없으면 원본을 보존하고 현재 자료와 같다고 꾸미지 않는다.
- 현재 기록은 같은 브라우저 임시 보관이다. 계정·서버 기록 DB·다른 기기 동기화는 추가하지 않는다.

수업 정의와 공개 projection은 서버 자료 조회가, 공용 요청·응답 검사는 순수 계약 모듈이 소유한다.
문항별 상태·이관·참조 검사는 화면과 분리해 직접 검사하고, 화면은 카드·대상·대화·입력을 조합한다.
사용량·Origin·본문 한도·응답 한도·timeout·취소·명시적 재시도의 비용 정책은 유지한다.

## 실제로 돌릴 경로

1. 단위: 공개 자료에 해설 없음, 문항·판·유형 대조와 비용 전 거절, 대상별 정본 맥락, 상태 이관·사건 참조.
2. 브라우저: 1번 답→2번 추가→1번 다시 질문·수정→지연 응답→쓰기형까지 진행→새로고침·보관을 실제 UI로 조작한다.
3. 실패: 이전 응답 지연·취소·재시도·저장 차단·잘못된 기록·자료 판 불일치·이미지 실패를 주입한다.
4. 빌드·Workers: 타입·단위·Cloudflare 빌드, 실제 Workers 브라우저와 운영 주소 조작을 구분한다.
5. 공급자: 자동 브라우저 검사는 모의 응답이다. 별도 격리 브라우저에서 실제 문항별 AI 응답을 확인하고 호출 수를 기록한다.

검증 입력은 강PD의 실제 수행이나 learn 기록으로 옮기지 않는다.

## 모델 유효성의 판단

각 예측은 반례 경로의 실제 관찰과 맞춰 지지·반박·미확인으로 기록한다. 구현 결함이 있으면 고친 내용과 원인을 구분한다.
모델의 빠진 관계 때문에 놓친 실패가 나오면 관계를 다시 검토한다. 테스트를 통과한 구현은 그 조건에서의 예측을 지지한다.
모델을 쓰지 않은 대조 작업이 없으므로 모델 때문에 개발 결과가 향상됐다는 인과 효과는 판단하지 않는다.
강PD가 사용하지 않았으므로 편리함·대상 이해·학습 효과도 미확인이다.
