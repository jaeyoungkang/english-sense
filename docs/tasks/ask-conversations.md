# 문장 해설의 기록과 이어 묻기

## 승인한 과업과 기대

2026-10-28 강PD가 문장 해설기의 해설 요청을 기록에 남기고, 요청 결과에 추가 질문할 수 있게 하도록 정했다.
`/ask/`의 영어 문장 해설과 한국어 변환을 모두 포함한다. 기존 수업의 판정·AI 대화·기록 형식은 유지한다.

물음은 “지난 해설을 다시 찾아 그때의 문장·결과와 앞선 질답을 보며 이어 물을 수 있는가”다.
요청별 원문·결과와 연결된 대화를 보존하면 이전 해설을 새 결과로 덮지 않고 생각을 이어 갈 수 있을 것으로 기대한다.
제작 모델 관계 1·2·3·6과 UX 모델 관계 2·3·9·12·13, 구조 모델 관계 6·9·16을 적용한다.
실제 입력→요청→결과→질문→다른 기록 선택→복원 경로로 기술 동작을 확인하고, 찾기 편한지는 강PD가 판단한다.

## 보관 범위와 정책의 상태

- 요청과 결과의 기록, 결과별 추가 질문은 승인됐다. 요청 문장·모드·요청 시각·해설 전문·추가 질문/답변·실패와 재시도 연결을 남긴다.
- 저장 정책은 별도 질문으로 제시했다. 개인 로그인 후 서버 보관·다른 기기 재개를 권고했고, 우선 브라우저 보관과 파일 내보내기라는 선택지도 제시했다. 실제 답변은 아직 없다.
- 답변 전에는 기존 수업과 같은 **브라우저 임시 복원 사본과 내보내기**를 준비한다. 서버 저장·개인 인증·다른 기기 동기화·study-and-learn 정본 이관의 완료로 취급하지 않는다. 브라우저 데이터를 지우면 잃을 수 있음을 표시한다.
- 학습 기록의 정본은 study-and-learn이다. 내려받기는 사용자 원문을 옮길 수 있게 하는 기능이며 정본 보관 확인이 아니다. 실제 학습 기록을 에이전트 문서나 검증 입력으로 복제하지 않는다.
- 기존 #5의 작업 공간 29개 보존 정책을 승인한 것으로 읽지 않는다. 이 과업의 새 저장 정책도 답변에 따라 계약과 구현을 맞춘다.

## 사용자 흐름과 실패

1. 문장과 모드를 골라 요청하면 요청 기록을 먼저 만들고 저장 성공 뒤 API를 호출한다. 새 결과는 새 기록에 붙고 앞선 기록을 덮지 않는다. 예시 해설은 실제 요청 기록으로 만들지 않는다.
2. 기록 목록에서 요청 문장·모드·시각·응답 상태를 보고 선택해 결과와 그 결과의 질답을 다시 읽는다. 선택·열람은 새 AI 요청이 아니다.
3. 선택한 결과 아래에서 질문한다. 해당 문장·원래 해설·성공한 앞선 질답을 함께 읽어 답하게 한다. 질문과 답변은 그 결과의 기록에 붙는다.
4. 요청 대기 중 다른 기록을 보거나 새 초안을 써도 응답은 요청 당시 기록/요청 ID에 붙인다. 초안은 결과별로 보존한다. 화면 선택으로 요청 대상을 바꾸지 않는다.
5. 실패는 요청·질문 원문과 함께 남기고 다시 요청은 새 ID로 연결한다. 재시도로 과거 실패를 덮지 않는다. 페이지를 떠날 때 대기는 결과 확인 못함으로 바꾸고, 종료 전 쓰기가 끝나지 않았으면 복원 시 바꾸며 자동으로 유료 재전송하지 않는다.
6. API 요청 전 브라우저 기록을 쓸 수 없으면 전송을 막고 원문을 화면에 남긴다. 받은 결과의 저장에 실패하면 결과는 화면에 유지하고 저장 실패·파일 내려받기를 안내한다.
7. 손상 기록은 원본을 덮지 않고 새 전송을 막으며 원본 내려받기를 제공한다. 다른 탭의 변경을 발견하면 덮지 않고 화면의 기록을 내보낸 뒤 새로고침하도록 안내한다. localStorage의 원자적 다중 작성자 처리를 보장하지 않는다.

## 맥락과 비용 경계

- 초기 해설 API의 입력 300자와 응답 스키마·영어/한국어 두 경로를 유지한다. 추가 질문은 `/api/ask-followup/`을 쓰며 수업 `/api/learn-chat/`과 합치지 않는다.
- 질문은 2,000자, 답변은 6,000자다. 원래 해설과 최근 성공한 질답을 최대 20메시지·16,000자로 전송한다. 오래된 질답을 전송에서 제외할 때 화면에 개수를 알리고 원기록은 지우지 않는다. 자동 요약으로 원문을 대체하지 않는다.
- 브라우저의 해설·질답은 비신뢰 자료다. 서버는 서버 감각 사전을 system에 두고, 원문과 과거 질답은 한 user 메시지의 자료로 전달한다. 과거 assistant 문자열을 검증된 서버 발화로 승격하지 않는다.
- 메서드·Origin·크기·정확한 계약·취소를 사용량 처리 전에 검사한다. 기존 일일 사용량 제한을 공유한다. 서버 공급자 60초·브라우저 90초 제한과 실패 뒤 입력/요청 보존을 확인한다.
- 결과 불명·재요청은 비용이 추가될 수 있음을 표시한다. 요청 ID는 응답 채택 식별자이며 서버의 유료 실행 멱등 보장이 아니다. 실제 질문·응답·키를 로그에 남기지 않는다.

## 책임과 호환

- `lib/ask-contract.ts`: 기존 Explanation 스키마와 후속 요청/응답·한도의 공통 순수 계약이다. 기존 서버 모듈에서 타입·검증을 다시 export해 호출 호환을 지킨다.
- `lib/ask-records.ts`: 실제 요청/질답 사실·초안·선택과 원문 검증·복원, 재시도 연결·대상별 응답 채택을 맡는다. 저장 위치와 서버 정본을 알지 않는다.
- `components/ask-record-store.ts`: 브라우저 복원 사본의 읽기·쓰기·실패와 다른 탭 변경 감지를 맡는다. 기존 수업 키에 닿지 않는다.
- `components/ask.tsx`: 문장 입력·기록 선택·결과와 이어 묻기, 대기/실패/내보내기다. 기존 `/ask/` URL·메타·공통 탐색·모드 키보드·단축키를 유지한다.
- `lib/server/ask-followup.ts`와 새 Route Handler: 요청 검증·사용량·공급자 호출·안전 응답을 맡는다. 개인 기록 저장/인증은 추가하지 않는다.

검증은 격리된 브라우저의 가상 입력으로 하며 실제 학습 기록과 섞지 않는다. 모의 AI 응답은 실제 공급자 성공이 아니다.
서버 보존·정본 이관·실기기·편리함 판단을 위 부분 검사로 완료 처리하지 않는다.
조건이 충돌하면 우회하지 않고 보고한다. 같은 확인을 고치고 다시 재는 일이 3회를 넘으면 원인을 보고하고 멈춘다.

## 2026-10-28 확인한 실행 범위

- `npm run check`: 타입과 단위 235개 통과. 해설기 기록 8개·후속 API 12개를 포함한다.
- `npm run cf:build`: Workers 산출물 생성 성공. 관련 브라우저는 최초 42개 중 새로고침 중단 경로 2개가 실패했다. 종료 이벤트보다 먼저 통신 실패를 남기던 실행 결함을 고친 뒤 42개가 통과했다.
- 이어 읽기 리뷰에서 bfcache/취소된 종료의 같은 인스턴스가 pending으로 남을 수 있음을 찾아, 종료 시 해당 요청만 unknown으로 바꾸도록 보완했다. 최종 해설기 브라우저 22개가 통과했다. 기존 두 모드·공통 탐색·메타/49주소·문장 재시도 회귀 22개와 합쳐 관련 고유 경로 44개다. 마지막 보완 뒤에는 변경한 해설기 22개만 다시 실행했다.
- 실제 폼으로 두 모드 요청·결과별 질답/초안·새로고침 복원·503/429 새 ID 재시도·늦은 응답 대상/읽기 위치·잘못된 응답 ID 거절·대기 중 수정 초안·기록 손상/쓰기 실패·동일 브라우저 두 탭 충돌·실제 JSON 내려받기를 확인했다. 페이지 종료 이벤트의 같은 인스턴스 재개는 합성 pagehide/pageshow로 확인했으며 실제 bfcache 적중은 측정하지 않았다.
- 320·390·1100·1440px에서 긴 질문/답변·기록 선택·폼의 44px 단추·가로 넘침을 확인했다. 1440·390px 입력/질답 스크린샷을 직접 보고 콘솔 예외와 가로 넘침이 없음을 확인했다. 편리함·실기기·Safari·스크린 리더·실제 200% 확대는 미확인이다.
- API 성공과 실패는 공급자 모의이며 유료 AI를 호출하지 않았다. 운영 반영과 실제 공급자 연결은 아직 확인 전이다. 로컬 로그·스크린샷은 `.git/ask-conversations-20261028/`에 있으며 실제 학습 기록은 넣지 않았다.

구조 영향은 reshape다. 공유 순수 계약·기록 모델·별도 브라우저 저장 경계와 후속 API를 추가했고 현재 구조 문서를 함께 맞췄다. 제작·UX·구조 모델에 기대어 구현했으며 모델·스킬의 새 보편 규칙으로 올릴 배움은 아직 합의하지 않았다.
