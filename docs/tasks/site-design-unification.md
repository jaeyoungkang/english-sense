# 공개 페이지의 디자인과 탐색 통일

## 과업과 승인 근거

- 과업: 기존 주소로 자료·연습·목록·문장 해설기를 열고, 수업 작업 공간과 같은 시각 체계와 탐색으로 학습을 이어 간다.
- 승인 근거: 강PD가 2026-10-28에 `/practice/`, `/reading/`, `/prep/`, `/ask/`의 디자인 변경을 지시했다([#6](https://github.com/jaeyoungkang/english-sense/issues/6)). 이슈 검토 뒤 보존 범위와 디자인 선택을 정리하게 했고, 이어 “모두 권고대로하라”고 승인했다.
- 현재 결정: 옛 셸 20페이지 전체를 통일하고, `/ask/`는 별도로 유지하며, 기존 목록 주소와 공통 수업 목록 창·탐색을 함께 제공한다. 이 문서는 승인한 범위와 동작의 작업 계약이다. 공통 탐색과 공개 페이지 디자인을 구현하고 로컬 Workers 검증을 마쳤다. 운영 반영은 아래 결과에서 구분한다.
- 현재 구현: 홈·이야기 15편·카드 13유닛은 작업 공간을 쓴다. 나머지 20페이지는 `components/site-shell.tsx`·`app/public-pages.css`의 공통 시각 체계와 분류 탐색을 쓴다. `app/layout.tsx`가 공개 목록 요약을 공급하고 모든 페이지의 `SiteNavigation`이 같은 창을 연다. 라우트의 분기는 `app/[[...slug]]/page.tsx`가 소유한다.
- 이번 물음과 기대: 같은 서비스에서 자료·연습·목록·해설기로 이동해도 무엇을 열었고 어디서 학습을 이어 갈지 같은 이름과 시각 위계로 알아볼 수 있는가. 공통 탐색과 시각 체계를 적용하면 수업과 목록 사이에서 탐색 방법을 다시 익히는 부담이 줄 것으로 본다.
- 기대의 근거: UX 모델 `knowledge/domain/web-app-ux-design.md` 관계 1·4·6, 제작 모델 `knowledge/domain/web-app-production.md` 관계 1·5·7이다. 같은 셸로 보인다는 자동 관찰과 실제 찾기 편하다는 사람의 판단을 나눈다.
- 실행이 모델을 따랐는지 가를 관찰: 처음 주소로 들어와 목록→수업→목록, 자료→연습, 수업→문장 해설기→돌아오기를 해 본다. 이동 경로·이름·입력 대상·기록 수명은 검사하고, 길을 쉽게 찾는지는 강PD의 사용으로 확인한다.

## 시작과 끝

- 시작 상황: 강PD가 기존 공개 주소·외부 검색·홈의 수업 목록·수업 안 링크 중 하나로 들어온다. 같은 브라우저에 수업 기록·질문 초안·노트가 있을 수 있다.
- 사용자 행동과 서비스 반응: 자료는 내려 읽으며 그림을 조작하고 관련 연습으로 간다. 목록은 기존 분류와 제목으로 수업을 고르게 한다. 수업에서는 목록을 다시 열거나 문장 해설기로 이동한다. 문장 해설기는 영어 해설 또는 한국어 변환을 고르고 문장을 보내 결과를 읽게 한다.
- 기대 결과: 같은 기능의 이름과 탐색 위치가 이어지고, 기존 주소에서 기존 자료와 기능에 도달한다. 같은 브라우저에 이미 보관한 수업 기록은 페이지 이동 후 기존 규칙대로 복원한다.
- 기다림·실패 뒤 다음 행동: 문장 해설 요청 중에는 진행 상태를 보이고 중복 전송을 막는다. 요청 실패·시간 초과·사용량 제한은 입력을 남기고 다시 시도할 수 있게 한다. 수업의 저장 실패·판정 실패·AI 실패 처리는 기존 수업 계약을 따른다.
- 이번 범위 밖: 학습 내용 수정, 새 수업·수업 AI 기능 통합, 퀴즈 풀이 방식 변경, 새 힌트·채점, #5의 보존 범위 구현, 서버 기록·계정·기기 간 복원·완료·숙달 판정, 옛 퀴즈 정답의 서버 이관이다. 배포는 구현·검증 뒤 세션의 외부 작업 승인 범위를 확인해 진행한다.

## 승인한 범위와 동작

강PD가 2026-10-28에 아래 세 권고를 모두 채택했다. 구현자는 같은 범위를 다시 묻지 않고 이 결정을 따른다.

| 결정 | 적용할 동작 | 선택한 이유 |
| --- | --- | --- |
| 옛 셸 20페이지 전체 통일 | 원리 5개와 장면 연습 5개까지 같은 시각 체계·탐색을 적용한다. 기존 퀴즈의 풀이 방식은 유지한다 | 자료에서 연습으로 이동할 때도 같은 디자인이 이어지게 한다 |
| 문장 해설기 별도 유지 | 공통 탐색의 “문장 해설기”에서 현재 탭의 `/ask/`로 간다. 영어 해설·한국어 변환을 유지하고 수업의 “AI에게 설명 요청”·질문 칸과 구별한다 | 기존 URL·기능·요청 경계를 보존하고 자유 문장과 문항 질문의 대상을 섞지 않는다 |
| 기존 목록 주소와 공통 탐색 유지 | `/practice/`, `/reading/`, `/prep/`, 작품별 목록을 유지한다. “수업 목록”은 같은 창을 열고 장면 연습·이야기 읽기·사전 훈련을 구분해 각 전체 목록·작품별 목록으로 연결한다 | 공개 주소와 각 분류를 보존하면서 수업에서 목록으로 가는 조작을 통일한다 |

현재 수업에서 링크인 “수업 목록”도 같은 창을 열도록 맞춘다. 현재 수업의 “이야기 전체 목록” 또는 “이 작품의 유닛 목록”은 창 안에 명시적으로 남긴다. 창은 제목·기존 주소·공개 요약만 쓰고 열기·닫기로 수행·AI 요청·질문 대상을 만들거나 바꾸지 않는다. “수업 목록”에 들어가는 장면 연습은 기존 다섯 주소로 연결하며 홈의 have 작업 공간과 `/practice/titanic/have/`를 같은 수업 기록으로 합치지 않는다.

자료는 수업 목록과 구별해 “감각 자료”에서 have·get·be·go·come으로 찾는다. 기존 `/#words`와 `/#resources`는 홈의 자료 창을 열며 다섯 자료와 공개 설명에 접근할 수 있다. 이 경로를 보존하면서 공통 탐색의 이름과 동작을 통일한다. 새 영구 주소를 만들 필요는 없다.

- 사용 뒤 판단할 질문: 문장 해설기와 수업 질문의 역할이 분명한가. 수업 목록과 감각 자료에서 원하는 내용을 쉽게 찾는가. 자료·목록·퀴즈가 같은 서비스로 느껴지는가. 페이지를 오가며 학습하기 편한가.

## 사용자 경험·디자인

시각 기준은 현재 작업 공간의 글자·색·간격·선·읽기 폭·단추 위계다. `app/workspace.css`와 `docs/ux-design.md`, UX 모델 관계 4를 대조해 공통으로 쓸 값을 고른다. 페이지마다 새로운 시각 규칙을 만들지 않는다.

- 자료 페이지: 제목→감각 설명·그림→예시→관련 연습 순서로 이어 읽는다. 실제 있는 항목으로만 목차를 만들고 그림의 설명·대체 정보를 유지한다.
- 목록 페이지: 무엇을 고르는 목록인지 제목으로 먼저 알리고 분류·이야기·작품·유닛의 위계를 보인다. 긴 제목·초안 표지·낱말 수·읽기 시간·기존 읽기 기록은 잘리거나 허위 진행률로 바뀌지 않는다.
- 장면 연습 페이지: 기존 문항 순서·보기 선택·힌트·모범 답·다음 문제·결과·재시작을 유지하며 화면 표현을 통일한다. have 작업 공간의 자유 문항 선택·AI 대화를 이 페이지에 자동으로 도입하지 않는다.
- 문장 해설기: 영어 해설과 한국어 변환의 두 모드, 예시 문장, 300자 제한, 예시 해설과 실제 결과의 구분을 유지한다. 입력·전송·대기·결과·오류를 읽는 순서가 분명해야 한다.
- 공통 탐색: 수업 목록·감각 자료·문장 해설기로 가는 이름과 조작을 페이지마다 맞춘다. 목록 창은 제목 있는 대화 상자로 열리고 Esc·닫기로 돌아오며 연 단추로 초점을 복원한다. 현재 수업의 저장 상태는 기존 실제 저장 결과로만 보인다.
- 목록·자료·해설기에는 없는 수업 기록, 저장 성공, AI 대화 칸이나 수행 상태를 채워 넣지 않는다. `WorkspaceFrame`의 모양을 얻기 위해 빈 목차·가짜 질문 대상·계정 저장 안내를 만들지 않는다.
- 1440·1100·390·320px와 200% 확대에서 본문·목록·입력·단추를 가리지 않고 읽고 조작할 수 있어야 한다. 키보드만으로 탐색·모드 선택·입력·전송·결과 확인·창 닫기에 도달한다. 초점 표시는 보이며 색만으로 상태를 구별하지 않는다.

이슈 검토에서 `docs/ux-design.md`의 문제 종류 표시·답 입력과 판정 위치·읽기 타이머 설명이 현재 코드와 어긋나는 것을 찾았다. 이번 현황 교정에서 기존 후속 결정과 현재 코드에 맞춰 로컬 문서를 바로잡았다. 본문 입력·본문 판정·대화 요약과 경과·남은 시간 표시를 유지하며, 이를 새 설계 선택으로 다시 묻지 않는다.

옛 장면 연습의 정답 서버 이관은 이 계약의 범위를 넘는다. 새 공통 클라이언트 모듈이 페이지·정본 JSON 전체를 import해 서버 전용 답이나 카드 내용을 새로 노출하지 않도록 경계를 대조한다.

## 구조 영향

- 영향: **reshape.** 저장·API·권한의 기대는 유지하지만 현재 수업 전용 셸과 옛 사이트 셸 사이에 공통 시각 체계·탐색 책임을 다시 나눈다. 실제 분리 위치와 `docs/architecture.md`의 현재 구조를 같은 구현에서 맞춘다. `SiteNavigation`은 공개 요약·창·초점을, `WorkspaceFrame`은 기존 수업 배치를 맡도록 나눴다.
- 현재 소유자: `WorkspaceFrame`은 수업의 목차·본문·대화·수업 상태를 배치하고, `SiteHeader`와 `StudyPartView`는 기존 공개 페이지·목록을 그린다. 목록 자료는 서버가 공개 요약으로 만든다.
- 선택한 경계: 공통 탐색은 공개 링크·목록 요약과 창의 열림·초점만 소유한다. 수업별 저장·노트·질문 대상·판정·AI 요청은 기존 소유자가 유지한다. 자료·목록·해설기는 수업 상태를 만들지 않는 틀에서 같은 시각 체계를 쓴다.
- 거부하는 대안: 비어 있는 `WorkspaceFrame` 슬롯을 가짜 수업 상태로 채우기, 모든 페이지·정본을 클라이언트 메뉴에 넣기, 자유 문장 해설을 수업 AI 요청으로 변환하기. 각 페이지의 실제 과업·상태·정답 경계와 어긋난다.
- 검증: 목록 요약의 공개 필드와 번들·첫 HTML·RSC를 대조하고 기존 `tests/import-direction.test.ts`, `tests/lesson-list.test.ts`, `tests/learning-catalog.test.ts`, `tests/card-recall.test.ts`의 경계를 확인한다. UI 이동은 실제 브라우저에서 기존 기록·요청과 함께 확인한다.

## 주소·메타데이터·호환 정책

- 기존 49개 공개 페이지를 모두 기존 주소에서 HTTP 200으로 유지한다. 목록을 공통 창에서 찾게 해도 `/reading/`, `/prep/`, 작품별 목록, `/practice/`, `/practice/titanic/`를 리다이렉트로 없애지 않는다.
- `/have.html`, `/get.html`, `/be.html`, `/ask.html`은 현재처럼 각 `/.../` 주소로 308 영구 이동한다(`next.config.ts`). 현재 지원하지 않는 `.html` 주소를 이미 지원하는 것으로 적지 않는다.
- 제목·description·canonical·OG·Twitter·기존 JSON-LD와 사이트맵의 페이지 대응을 보존한다. 실제 페이지가 없는 자료 목록 주소를 canonical이나 메뉴에 지어 넣지 않는다.
- 기존 카드 `#<카드 id>`와 본문 앵커 링크, 작품별 유닛·짝 이야기·이웃 유닛 링크를 보존한다. 공통 탐색 도입으로 수업 내용에 도달하는 기존 딥링크를 바꾸지 않는다.
- 학습 v3·수업 기록 v4·자료 UI·레이아웃·노트의 기존 키와 저장 범위를 유지한다. 목록을 열기만 해 수행·선택·질문·AI 요청을 합성하지 않는다. `/ask/`의 미전송 입력·결과는 현재 페이지 메모리 수명이며 새 영속 복원을 약속하지 않는다.

## 변경 범위와 구현 인계

- 필요한 경로: 라우트의 페이지 조합, `components/site-shell.tsx`, `components/study-pages.tsx`, `components/lesson-list-dialog.tsx`, 수업 도구 막대와 공통 탐색, 기존 그림·퀴즈·해설기 표시, `app/globals.css`·`app/workspace.css`의 시각 체계, 관련 검사다. 데이터 조회는 기존 서버 공개 투영을 재사용한다.
- 함께 맞출 문서: 이 계약, 실제 시각·탐색을 소유하는 `docs/ux-design.md`, 공통 셸 책임을 소유하는 `docs/architecture.md`다. 학습 약속의 의미가 그대로면 `docs/learning-service.md`의 요구를 새로 정하지 않는다.
- 살펴보되 이번에 구현하지 않을 것: #5의 풀이 보존, #4의 서버 저장·인증·다른 기기 복원, 옛 퀴즈의 서버 정본화다. #5가 먼저 구현되면 저장 형식을 임의로 고정하지 말고 그 계약에 맞춰 회귀 기준을 갱신한다.
- 최소 실행: 구현 단계에서 목록 1개·자료 1개·장면 퀴즈 1개·해설기와 수업 1개의 탐색 왕복으로 공통 틀을 대조한다. 가짜 대화나 빈 수업 상태 없이 읽기·입력 폭을 확보할 수 없는 경우 전체 페이지로 넓히기 전에 설계를 재검토한다.
- 구현에 넘길 것: 이 계약, `shared-skills/web-app-implementation/SKILL.md`와 배경 모델, `docs/ux-design.md`·`docs/architecture.md`, 기존 수업·come 연습 계약, 수정 범위와 위 멈춤 규칙이다. 구현과 로컬 검증을 마쳤다. 이후 변경도 같은 계약과 공개·기록 경계를 따른다.

## 결과

- 확인한 범위: 코드·주소 생성 경로를 읽고 옛 셸 20페이지, 기존 작업 공간 29페이지, 목록·정답·해설 요청의 현재 경계를 대조했다.
- 승인한 것: 옛 셸 20페이지 전체 통일, 별도 `/ask/` 유지, 기존 목록 주소와 공통 수업 목록 창·탐색이다.
- 구현: 공개 20페이지의 시각 체계·분류 탐색, 전 페이지의 공통 수업 목록·감각 자료·문장 해설기 이동, 별도 해설기의 입력/결과 배치를 맞췄다. 저장·판정·AI 요청 계약과 기존 주소를 유지했다.
- 검증: 타입·단위 215개, Workers 빌드, 전체 e2e 338개 통과·2개 건너뜀이다. 1차 전체 실행의 세 종류 실패는 자료 이름의 선노출(자료 창으로 한정), 모달 Tab 경계(순환 보완), 정적 상단 도구막대로 돌아오는 노트 검사(명시적 스크롤 후 기존 hit-test 유지)로 원인을 나눠 수정했다. 2차 전체 실행에 실패가 없다.
- 시각: 자료·목록·작품별 목록·퀴즈·해설기 대표 5종×5폭(1440·1100·720·390·320px)에서 가로 넘침이 없다. 실제 화면과 입력/결과 읽는 순서도 검토했다. 실제 200% 확대·Safari·스크린 리더·통일감과 편리함의 사람 판단은 남는다.
- 운영: 배포 대기다. 실제 AI 공급자 성공·실기기 검증은 이번 로컬 근거에 포함하지 않는다.
- 사용자 판단이 남은 것: 구현 뒤 실제 사용에서 통일감과 찾기 편한 정도를 판단한다.
