# come 연습 페이지와 빈칸 넣기 문제

## 과업과 승인 근거

- 과업: 강PD가 타이타닉 장면으로 come을 연습한다. go 연습 페이지처럼 고르기를 풀고, come-1에서 처음 한 빈칸 넣기를 같은 페이지에서 쓴다.
- 승인 근거: 2026-10-28 강PD의 결정. "사이트에 come을 더하라"는 지시에서 이어졌고, 빈칸 넣기(`fill`) 형식으로 go와 같은 범위의 연습 페이지(`/practice/titanic/come/`)를 만들기로 했다. 문제의 정본은 study-and-learn의 `content/scene-sense/problems.jsonl` `come-1-*` 일곱 줄이고, 강PD의 실제 풀이는 `learn/english-as-germanic/attempts.jsonl`에 있다.
- 현재 구현: `/practice/titanic/go/` 같은 연습 페이지는 `content/pages.json`의 `quiz` 부분을 `components/quiz.tsx`가 그린다. 형식은 `choose`(고르기)와 `produce`(쓰기) 둘이다. `fill`은 없다. 정적 퀴즈는 정답·해설이 페이지 props에 실려 가고 화면만 답을 낸 뒤에 보여 준다(`docs/tasks/workspace-lessons.md` 정리 대상으로 이미 적힌 한계이며 go와 같다).
- 이번 물음과 기대: `fill` 형식을 더해도 기존 `choose`·`produce` 동작은 그대로이고, come 연습 페이지가 go와 같은 범위(고르기 다섯 + 쓰기 쪽 둘)로 열린다.
- 기대의 근거: `knowledge/domain/web-app-production.md`의 정본·공개 시점 규칙, UX 모델의 "답을 내기 전에 정답을 보이지 않는다".
- 가를 관찰: 답과 힌트가 요청 전 화면 글자에 없는지, 기존 have·go 연습 e2e가 그대로 통과하는지.

## 시작과 끝

- 시작 상황: 강PD가 `/practice/titanic/` 목록에서 come 연습을 연다.
- 사용자 행동과 서비스 반응:
  1. 고르기 다섯 문제는 go와 같다. 선택지를 고르면 선택지 종류(영어식·한국어식 직역·라틴어 계열)와 이유, 감각 설명이 나온다.
  2. 빈칸 넣기 두 문제는 책의 앞 문장, 빈칸이 든 문장, 뒤 문장과 한국어 뜻(`hint_ko`)을 보인다. 강PD가 빈칸에 들어갈 말을 영어로 쓴다.
  3. 막히면 "힌트 보기"를 누른다. 한 번 누르면 쓸 동사(`hint_verb`), 한 번 더 누르면 쓸 말(`hint_words`)이 나온다. 힌트는 누르기 전에 화면에 없다.
  4. "모범 답 보기"를 누르면 책 문장 그대로의 정답, 감각 설명, 처음 푼 학습자가 고친 곳이 나온다.
- 기대 결과: 마지막 문제 뒤 고르기 결과(5 / 5 형식)와 처음부터 다시가 go와 같이 동작한다. 빈칸 넣기는 점수에 넣지 않는다.
- 이번 범위 밖: 서버 판정, 빈칸 답 저장·복원, 정적 퀴즈의 정답 서버 이관(별도 결정), 새 로드맵 유닛, do를 표제어로 올리는 일.

## 사용자 경험

- 판단 단위와 맥락: 한 문제가 한 화면이다. 빈칸 문제는 책 문단 안에서 빈칸의 자리를 보인다.
- 상태와 공개 시점: 풀기 → (힌트) → 모범 답 순서다. 힌트와 모범 답은 요청해야 나온다.
- 조작·접근성: 입력은 기존 `produce`의 텍스트 영역과 같고, 새 버튼은 이름이 있는 `button`이다. 320px에서 가로 넘침이 없어야 한다.
- 시안과 실제 동작의 경계: 판정은 없다. 빈칸 답을 저장하지 않으며 새로고침하면 처음 문제로 돌아간다(go와 같다).

## 구조 영향

- 구조 기대의 변화: 없음. 상태 수명·권한·외부 호출이 그대로다.
- 영향: none. `lib/content.ts`에 `FillQuestion`을 더하고 `Quiz`가 한 갈래를 더 그린다. 하나뿐인 소비자인 have 서버 카탈로그는 `fill`을 걸러 낸 목록을 받는다(have 페이지에는 `fill`이 없어 결과가 같다).

## 변경 범위와 구현 인계

- 필요한 경로: `lib/content.ts`, `components/quiz.tsx`, `lib/server/learning-catalog.ts`, `content/pages.json`(연습 페이지, 원리 페이지 절, 허브 문구), `content/site.json`, `public/assets/og/titanic.png`, 테스트.
- 살펴보되 고치지 않을 것: 정적 퀴즈의 정답 서버 이관, 연습 페이지의 풀이 기록.
- 구현에 넘길 것: 이 계약, `shared-skills/web-app-implementation/SKILL.md`, 위 배경 모델. 기존 `choose`·`produce`의 동작이 달라지거나 기존 검사가 깨지면 멈추고 보고한다.

## 사람이 정할 질문

- 새로 정할 선택: 없음.
- 사용 뒤 판단할 질문: 힌트가 두 단계인 것이 도움이 되는지, 고르기 이유 글이 읽을 만한지는 강PD가 쓴 뒤 판단한다.

## 결과

- 확인한 범위: 위 표의 다섯 조건. `fill` 형식, come 연습 페이지(고르기 5, 빈칸 넣기 2), 허브·홈 문구, `site.json`, 타이타닉 링크 미리보기 이미지.
