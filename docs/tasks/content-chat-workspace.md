# 콘텐츠를 보며 AI와 대화하는 작업 공간

## 승인과 문제

강PD는 문서형 화면에서 콘텐츠가 가려져 어색하다고 평가하고 콘텐츠와 채팅을 옆 칸에 두자고 제안했다.
같은 맥락과 같은 세로 배치를 구별하고, 넓은 화면에서 문서·대화를 각각 스크롤하며 목차를 접는 방향을 설명했다.
강PD는 “좋다. 개선 진행해봐”라고 승인했다. 모델을 먼저 고치고 실제 테스트로 예측을 대조한다.
이전 배치의 자동 검사는 통과했지만 사용자의 읽기 편의를 확인하지 못했다. 이전 근거는 `document-workspace.md`다.

## 만들 동작

- 넓은 화면에서는 접을 수 있는 목차, 콘텐츠 문서, AI 대화를 나란히 둔다. 콘텐츠와 대화는 각각 스크롤한다.
- 감각 자료·퀴즈·최초 답 입력은 콘텐츠 칸에 둔다. 카드 안의 수행 열람은 유지한다. 대화 입력은 채팅 칸 안에 둔다.
- 콘텐츠는 실제 추가한 자료와 카드에서 만든다. 채팅은 학습 사건 전체를 실제 순서로 표시한다. 카드 사건은 본문으로 가는 표식으로 보이며 퀴즈 본문·입력 폼을 중복하지 않는다.
- 최초 답·수정·대화·준비 안내·실패·취소·재시도·이전 묶음·새 대화 사건을 빠뜨리지 않는다. 수정 입력은 명시한 퀴즈를 대상으로 한다.
- 넓은 화면에서 목차·감각 자료 열람은 콘텐츠만 이동한다. 전송·새 응답은 채팅만 이동하고 콘텐츠 위치·초안을 바꾸지 않는다. 과거 채팅을 읽는 중에는 새 응답을 알리고 이동을 선택하게 한다.
- 질문 대상은 명시적 선택으로 바꾼다. 채팅의 본문 참조는 읽기 이동이며 질문 대상이나 초안을 바꾸지 않는다.
- 자료 스택은 콘텐츠 칸에 한정한다. 최근 추가 순서·하나 펼침·재펼침 시 본문 순서 유지와 기존 자료 추가 기능을 보존한다.
- 좁은 화면은 콘텐츠 다음에 대화를 자연스럽게 이어 보인다. 전역 고정 자료·입력으로 본문을 누르지 않으며 탭 전환 없이 양쪽에 도달한다. 명시적인 콘텐츠·대화 이동으로 페이지를 움직일 수 있으며 각 재개 위치·초안·질문 대상을 보존한다. 새 응답이 콘텐츠 읽기를 강제로 이동시키지 않는다.

넓은 화면의 두 칸 폭과 긴 본문·응답의 동시 표시를 렌더링해 확인한다. 단순히 본문 높이가 40px보다 크다는 조건으로
읽기 가능성을 대신하지 않는다. 실제 편리함은 강PD가 자료를 보며 질문하는 과업을 해 본 뒤 판단한다.

## 상태와 실행 경계

구조 영향은 reshape다. 학습 상태 소유자와 API는 그대로이며 두 표시 영역과 읽기 위치의 담당을 나눈다.
`lib/learning-workspace-state.ts`의 v3·정본·API 계약을 바꾸지 않는다. 새 학습 사건을 지어 넣지 않는다.
콘텐츠는 기존 `buildDocumentNodes`의 자료·카드 부분을, 채팅은 `record.events` 전체를 표시한다. 원본 사건 배열은 정렬·이관하지 않는다.
기존 문서 UI v1의 자료·앵커는 읽기 호환을 유지한다. 목차 접힘과 채팅 읽기 설정은 별도 UI 키에 보관하며 유효한 값만 사용한다.
콘텐츠는 저장한 본문 앵커로, 채팅은 저장한 스크롤 위치 또는 끝 따라가기 정책으로 복원한다. 크기가 달라지면 유효 범위로 제한한다.
모바일의 페이지 이동과 넓은 화면의 내부 스크롤은 구분한다. 복원 자체가 전송·초안 제출·학습 완료를 만들지 않는다.

현재 공개 have·get·be·go 자료, have 일곱 문항과 현재 공급자·한도·이관 정책을 유지한다. 서버 저장·계정·come 유닛은 범위 밖이다.
실제 실행은 새 Cloudflare 산출물의 Workers에서 검증하고, 기존 승인 범위로 운영 반영·AI 연결을 확인한다.

## 모델 판단

사용자 피드백으로 단일 세로 배치의 읽기 가설을 수정했다. 기존 상태·귀속 검사의 통과는 그 가설의 지지 근거가 아니었다.
이번 결과도 동시 표시·위치 보존·조작을 확인한 범위에서만 판정한다. 사용자 사용감·학습 효과와 모델의 인과 효과는 별개다.
