# 목차가 생기는 학습 문서와 감각 자료 스택

## 승인과 범위

강PD는 상단 자료가 스택으로 쌓이고, have를 다시 펼치면 다른 자료는 접힌 채 남는 구성을 승인했다.
이어 쌓인 항목이 목차가 되며 도큐먼트를 기본으로 채팅도 함께 쌓이는 새로운 디자인을 요구했다.
모델을 먼저 갱신하고 실제 테스트로 유효성을 판단하는 기존 지시를 따른다.
UX 관계 12·13·16·17, 규칙 2·8·12~17을 이번 구현의 배경으로 삼는다.

본문은 읽기 폭을 가진 문서다. 실제 추가한 감각 자료와 퀴즈가 목차에 나타나고, 제출·수정·AI 대화는
발생 순서대로 이어진다. 상단 자료 스택은 최근 추가 자료를 위에 두고 하나만 자세히 펼친다.
이것은 현재 have 일곱 퀴즈의 새 디자인이며 유닛 진도를 새로 판정하거나 다음 학습을 자동 개방하지 않는다.
다중 자료 동작은 이미 공개한 have·get·be·go의 감각 설명으로 실제 검증한다.
come의 대화형 학습은 아직 연결하지 않는다. 감각 자료 열람과 have 퀴즈의 질문 대상을 구분한다.

## 실행 경계

학습 v3와 API 계약·정본 일곱 문항은 유지한다. 공개 감각 자료는 기존 페이지의 공개 필드에서 안전하게 가져온다.
자료 추가·펼침·목차 읽기 위치는 별도 UI 상태다. 이 상태로 학습 수행이나 사용자 정본 진도를 만들지 않는다.
본문·목차·상단 스택은 같은 자료 ID를 사용한다. 문서 본문은 추가 순서, 스택은 최근 추가 순서로 표현한다.
자료 추가 시점의 본문 위치는 당시 사건 ID에 연결하되 학습 사건의 저장 순서는 바꾸지 않는다.
UI 상태가 손상되거나 본문 위치를 찾지 못해도 실제 학습 기록과 질답을 버리지 않는다.
삽입 앵커를 잃은 자료는 원위치를 추정하지 않고 위치 미확인 안내와 함께 문서 끝에 보관한다.
이 손상 복구에서는 자료끼리의 원래 순서가 달라질 수 있으며 실제 학습 사건 순서는 유지한다.

기존 공개 이미지·도식을 활용하고 자료 로딩 실패 시 본문·대체 설명을 제공한다.
한 문서에 다루는 자료와 AI가 답하는 퀴즈가 다르면 둘을 글로 표시한다. 미전송 초안은 자동으로 보내지 않는다.
새 서체·간격·문서 위계는 실제 브라우저에서 확인하며 독립 검토와 기존 실패 경로 검사도 수행한다.
운영 배포와 실제 AI 호출은 기존 승인 범위에서 실행하되 화면 변경과 서버 변경을 구분해 근거를 남긴다.

## 모델 판단

구현 전에 위 조건을 정했다. 실제 동작·실패·수정을 결과에 채워 관계의 예측을 대조한다.
조작 검사는 사람이 문서를 더 잘 이해했다는 근거가 아니다. 실제 사용성·선호·학습 효과와 모델의 인과 효과는 미확인이다.

## 실제 관찰

모델·계약을 `645017d2fcdf6aa186195deaa5b1b94024ab3ec3`, 스킬 배경 판을 `bfef2a8`에 먼저 커밋했다.
2026-10-26 최종 타입·단위 61개, Cloudflare 빌드와 로컬 Workers 브라우저 40개가 통과했다.
40개는 새 문서 검사 10개, 기존 학습 20개와 기존 페이지 10개다. 자동 검사의 AI 응답은 모의다.
학습 v3·대화 API·일곱 정본 문항의 의미와 저장 형식은 바꾸지 않았다.
루트 빌드 HTML과 클라이언트 JS 7개에서 비공개 해설·모범 답·교정 자료 34개 문자열이 없는 것도 대조했다.
이는 공개 자료 전달과 특정 산출물의 검사이며 전체 보안 감사는 아니다.

초기 Workers 검사에서는 34개가 통과하고 6개가 실패했다. 독립 검토와 실제 화면 확인도 함께 사용했다.

자료 앵커를 잃으면 본문 끝으로 보관하는 예외를 독립 검토로 명시하고, 안내·목차 연결·v3 불변을 검사했다.
정상 순서·귀속·복원·초점의 실행 예측은 이 조건들에서 지지됐다. 모델을 읽어도 구현 누락은 남아 독립 검토와 실행이 필요했다.
강PD의 사용 관찰과 모델 없는 대조 개발은 없어 편리함·학습 효과·개발 향상의 인과 효과는 판단하지 않는다.
실제 iOS 키보드·화면 읽기 도구, 계정·서버 저장·기기 간 동기화와 come 학습은 미확인 또는 미구현이다.
이번 배움은 단일 앱의 초기 적용 조건이어서 공용 베이스에 보편 효과로 제안하지 않았다.
