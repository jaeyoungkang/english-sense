# 장면·수행·AI 대화를 잇는 학습 작업 공간

## 과업과 승인 근거

2026-10-26 강PD는 이미지를 적절히 배치하고 터미널처럼 AI와 대화하도록 만들 것을 지시했다.
이어서 현재 시안이 웹페이지처럼 보인다고 지적했다. 기존 소개 중심 시안을 기본 학습 화면으로 삼지 않고,
실제 Next.js 앱의 첫 화면에서 장면·내 수행·AI 대화가 이어지는 작업 공간을 만든다.
요구사항은 `docs/learning-service.md`, 설계 판단은 UX·아키텍처·Next.js 모델을 따른다.

기대는 같은 문제의 자료·수행·질답이 한 작업 공간에 있으면 질문할 때마다 맥락을 다시 설명하지 않고
답을 고치고 이어 갈 수 있다는 것이다(UX 모델 관계 2·3·5·9, 아키텍처 모델 관계 6·9·16).
실행이 이를 따르는지는 실제 전송 문맥·대화 보존·늦은 응답 채택과 화면 조작으로 가른다.
이것이 편리한지는 강PD의 사용 뒤 판단한다. 기존 시안의 사용성이 확인됐다고 해석하지 않는다.

## 이번 구현

- 실제 have 책 장면 한 문제를 첫 학습 작업 공간에 연결한다. 다음 로드맵 유닛이라고 정하지 않는다.
- 장면 재구성 이미지와 감각 도식을 서로 다른 역할로 배치한다. 정답을 그림에 적거나 선택지의 종류를 먼저 드러내지 않는다.
- 처음 답·이유·수정·직접 보낸 질문을 구분하며 AI의 응답을 같은 장면의 대화로 잇는다.
- 서버가 정본 문제·감각 자료를 조회하고 제출한 수행과 이전 대화를 제한된 맥락으로 결합한다.
- 새 `/api/learn-chat/`가 실제 공급자를 호출한다. 기존 300자 문장 해설 API와 다른 계약이다.
- 최초 제출 전에는 준비된 과업 안내를 제공하고 그 출처를 표시한다. 이번 버전의 제출 전 안내는 생성형 힌트 대화까지 제공하지 않는다.
- 최초 제출 뒤 AI 피드백·설명·추가 질문을 여러 차례 이어 간다. AI가 다음 문제·학습 완료를 자동 확정하지 않는다.
- 브라우저 초안·처음 제출·수정·대화와 작성 중 메시지를 임시 보관한다. 개인 서버 저장·인증·다른 기기 동기화는 이번 구현에 포함하지 않는다.

터미널 learn의 문제별 대화·즉시 피드백·내용과 말의 막힘 구분을 참고했다. 학습 자료의 정본은
study-and-learn의 영어 학습 모델·learn-session·scene-sense다. 이번 작업은 learn 수행이 아니며 학습 기록을 만들지 않는다.

## 상태·정책과 구조 영향

운영 코드 영향은 `reshape`다. 기본 화면의 콘텐츠 조합에 학습 작업 공간을 연결하고, 별도 다중 턴 HTTP 진입점을 둔다.
기존 정적 자료·문제 주소·문장 해설 API는 유지한다. 영속 서버 상태는 기존 일일 한도뿐이다.
기존 한도 함수·Origin 검사·공급자 설정을 재사용하고, 대화용 코드가 별도 한도 규칙을 만들지 않는다.

| 정책 | 결정·담당 | 현재 한계 |
| --- | --- | --- |
| 대화 맥락 | 정본 문제는 서버가 구성하고 브라우저의 수행·과거 대화는 신뢰하지 않는 학습 자료로 취급한다 | 인증된 수행의 서버 정본은 없다 |
| 공개 순서 | 준비 안내·일반 감각 자료는 제출 전, 해당 문제의 생성형 피드백은 제출 후 | 제출 여부는 개인 저장이 없는 현 단계에서 브라우저의 제출 자료를 형식 검증한다. 신뢰할 수 있는 학습 이력 인증은 아니다 |
| 입력 전송 | 보내거나 제출한 내용만 공급자에 전달한다 | 미전송 초안을 몰래 전송하지 않는다 |
| 생성·저장 | 실제 AI 응답과 브라우저 임시 보관을 별도로 표시한다 | 서버 대화 기록·기기 간 복원 없음 |
| 비용·재시도 | 기존 일일 한도와 timeout·크기 제한. 실패한 요청만 명시적으로 재시도한다 | 취소·timeout 뒤 외부 비용이 안 생겼다고 보장하지 않는다. 서버 멱등 재전송은 미구현 |
| 대화 길이 | 공용 계약의 메시지 수·문자 제한을 UI·서버에서 확인한다 | 맥락을 조용히 잘라서 연속 대화라고 보이지 않는다 |

요청·응답 계약은 `lib/learning-chat-contract.ts`, 현재 처리 순서와 책임은 `docs/architecture.md`가 소유한다.
실패 시 이전 메시지를 중복 추가하지 않고, 새 실행 뒤 응답은 request 식별성과 현재 작업에 맞을 때만 붙인다.
브라우저 임시 기록은 study-and-learn의 수행·배움으로 자동 반영하지 않는다.

## 사람이 사용한 뒤 판단할 것

장면과 대화를 오가며 답하기 쉬운가, 이미지가 이해에 도움이 되는가, 터미널의 질답을 웹에서 자연스럽게 이어 가는가.
실제 응답은 아직 없다. 키보드·전송·복원 검증을 사용성·학습 효과로 대신하지 않는다.

## 실제 실행과 검토

2026-10-26 `npm run check`의 타입·33개 단위 검사, `npm run cf:build`, 로컬 Workers의 PC·모바일 16개 브라우저 검사가 통과했다.
운영 주소에서는 기존 14개 브라우저 경로와 실제 공급자 다중 대화를 별도로 확인했다. 이미지 실패·저장 차단·IME 두 검사를
추가한 뒤 해당 학습 작업 공간 6개 검사가 최종 배포에서도 통과했다. 새 대화의 이전 이력 보관·수행 유지·빈 대화 맥락도 확인했다. 테스트의 모의 AI 응답은 실제 호출의 증거로 쓰지 않는다.

운영 브라우저에서 검증용 최초 답·이유를 제출하고 AI 응답을 받은 뒤, 이전 답을 짚는 추가 질문에 실제 응답을 받았다.
두 번째 요청의 이력에 첫 AI 응답이 들어 있음을 확인했고 새로고침 뒤 새 유료 요청 없이 두 응답이 복원됐다.
검증용 입력은 임시 브라우저에서만 사용했고 강PD의 learn 기록·배움으로 저장하지 않았다.

독립 서버·프런트 리뷰를 거쳤다. 모바일 기록 진입 누락, 작은 안내·상태 글자의 낮은 대비, hydration 전 이미지 실패 시
대체 그림이 나타나지 않는 문제를 고쳤다. 새 API의 실제 정확성·강PD의 사용성·장기 개인 기록은 이 검사로 확정하지 않는다.
빈 수행 상태의 실제 화면은 `design/screenshots/workspace-*.png`에 있다.
