# 시간 제한 읽기와 책·영화 사전 훈련

## 과업과 승인 근거

- 과업: 짧은 이야기를 정한 시간 안에 읽고 곧바로 퀴즈를 푼다. 책이나 영화를 보기 전에 그 작품에 자주 나오는 표현을
  카드로 익히고 빈칸 문제를 푼다.
- 승인 근거: 2026-10-27 강PD가 study-and-learn의 읽기·책 사전 훈련·영화 사전 훈련 자료를 웹앱에도 추가하기로 했다.
  공개 범위도 정했다. 매직트리하우스 연습 페이지처럼 공개하고, 책·영화 문장은 카드마다 출처(작품명, 저자나 연도, 부 번호나
  타임코드)를 붙여 한 문장씩만 싣는다. 이야기 두 편은 '초안' 표시를 달아 올린다.
- 정본: study-and-learn의 `content/reading/`, `content/book-prep/`, `content/movie-prep/`. 웹앱은 가져오기 스크립트로
  만든 JSON(`content/reading.json`, `content/prep.json`)만 쓴다. `input/`의 원문은 가져오지 않는다.

## 시작과 끝

- 읽기: 목록 → 이야기 → 시작 → 남은 시간을 보며 본문 읽기 → 시간이 끝나거나 '다 읽었습니다'를 누르면 본문을 가리고 퀴즈 →
  문제마다 고르면 정답과 해설 → 점수와 읽은 시간.
- 사전 훈련: 책·영화 목록 → 작품(부와 화자, 유닛마다 언제 할지) → 유닛. 카드마다 표현, 작품 안의 횟수, 뜻, 감각, 근거,
  출처를 붙인 예문, 빈칸 문제가 있다. 빈칸에 쓰고 확인하면 맞고 틀림을 보이고, 틀리면 다시 쓰거나 답을 볼 수 있다.
- 이번 범위 밖: 기록 저장(서버·계정), AI 해설 연결, 숙달·완료 판정, 학습 작업 공간(`/`)과 그 상태.

## 구조 영향

none에 가깝다. 새 공개 페이지는 기존 `[[...slug]]` 경로와 `lib/content.ts`의 페이지 목록에 더해 같은 메타데이터·
sitemap·이동 경로를 쓴다. 읽기·빈칸 상태는 화면 안에서만 살고 저장하지 않는다. 퀴즈 정답과 해설은 공개 자료이므로
브라우저에 함께 보낸다.

## 사람이 정할 질문

- 사용 뒤 판단: 3분이 빠듯한지, 빈칸 비교가 너무 관대하거나 엄한지, 한 카드에 출처가 붙은 영화 대사(자막 한 줄에 짧은
  문장이 둘 이상인 경우가 있다)가 공개 기준에 맞는지.

## 결과

2026-10-27 `npm run check`(타입·단위 79개), `npm run cf:build`, 로컬 Workers(`wrangler dev`)에서 `npm run test:e2e` 66개가
통과했다. 운영 주소에는 배포하지 않았다. 3분이 알맞은지, 카드 학습이 책·영화를 편하게 만드는지는 강PD가 써 본 뒤 판단한다.

## 추가: 사전 훈련 짝 이야기 (2026-10-27)

- 승인 근거: 강PD가 사전 훈련에 퀴즈만이 아니라 읽기 콘텐츠도 넣고, 시간 제한 읽기에 각각 더하기로 했다.
- 정본: study-and-learn `content/reading/README.md`의 짝 이야기 표(짝 유닛 열), `stories/prep-*.md` 13편,
  `quizzes.jsonl`의 `expression` 문제(`card`에 카드 id).
- 가져오기: README에서 머리에 `이야기`·`제목`·`낱말`·`제한 시간`·`상태`가 있는 표를 모두 읽고(`tableRecords`), `짝 유닛`
  열을 `pair`로 옮긴다. `expression` 문제는 `card`가 있어야 하고 짝 이야기에만 있어야 한다. 짝 유닛이 사전 훈련에 없거나
  카드가 그 유닛에 없으면 실패한다(`checkPairs`).
- 화면: `/reading/`은 일반 이야기와 짝 이야기를 나누고, 짝 이야기는 작품별로 묶어 유닛을 적는다. 짝 이야기 페이지는
  "<작품> 유닛 N 표현으로 쓴 이야기입니다"와 유닛 링크를 보인다. 퀴즈의 표현 문제에는 '표현'을 달고 해설 뒤에 카드
  링크(`/prep/<작품>/unit-N/#<카드 id>`)를 둔다. 유닛 페이지 카드 아래에 "이 표현으로 읽기: <제목> (N분)" 링크를 둔다.
  카드 `article`에 카드 id를 앵커로 달았다.
- 결과: 정본에서 이야기 15편(짝 13편)·문제 105개. `npm run check`(타입·단위 81개), `npm run cf:build`, 로컬 Workers에서
  `npm run test:e2e` 72개(기존 66개와 새 6개, PC·모바일)가 통과했다. 새 e2e는 목록의 묶음, `prep-wonder-3`의
  시작→퀴즈→표현 문제 해설의 카드 링크 이동, 유닛 페이지의 읽기 링크를 실제로 눌러 확인한다. 배포하지 않았다.
