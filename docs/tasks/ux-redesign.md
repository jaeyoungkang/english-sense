# UX 모델과 앱 디자인 재설계

## 과업과 승인 근거

2026-10-26 강PD는 웹앱 사용자 경험 설계 모델을 준비하고 앱 디자인을 처음부터 다시 하도록 지시했다.
이어서 Lighthouse의 계약 설계부터 엔지니어링 방법까지 상세히 참고하도록 지시했다.
이번 산출물은 UX 모델, 출처 조사, 앱 디자인 제안과 조작 가능한 프로토타입이다.
기존 색·카드·메뉴를 유지한다는 전제를 두지 않는다. 학습 내용의 정본과 여섯 요구는 `docs/learning-service.md`를 따른다.

현재 구현은 공개 자료·퀴즈·단문 해설기다. 선택 즉시 피드백을 보이고, 개인 수행 저장·인증·재개는 없다.
이번 의문은 장면과 답안을 중심에 두고 제출·피드백·수정·재개를 구분하면 다음 행동과 기록의 차이가 드러나는가다.
기대의 근거는 `knowledge/domain/web-app-ux-design.md` 관계 1·2·3·5·9·10이다.
이해와 편리함은 미확인이며, 에이전트는 상태 구분·입력 보존·조작 가능성만 먼저 확인한다.

## 시작과 끝

빈 상태에서 기존 자료의 연습 한 문제를 열고, 답과 이유를 제출한 뒤 출처가 있는 기존 해설을 읽는다.
스스로 고친 답과 질문을 별도로 남기고 나갔다가 같은 브라우저에서 작성 맥락을 복원한다.
프로토타입의 입력은 시안 내부에서만 사용하며 study-and-learn의 학습 기록으로 보내지 않는다.
기록은 사용자가 시안에서 직접 입력한 값으로만 만들고, 예시를 강PD의 수행으로 표시하지 않는다.

## 구조 영향과 구현 범위

영향은 운영 앱에 `none`이다. `design/prototype/`에 별도 정적 시안을 두며 Next.js 경로·API·인증·저장을 바꾸지 않는다.
프로토타입의 localStorage는 동작을 비교할 임시 수단이다. 운영 저장 설계나 앱 아키텍처로 확정하지 않는다.
실제 화면 교체는 이 제안을 검토한 뒤 Next.js의 콘텐츠·레이아웃·상태 책임에 맞춰 구현하고 별도 수용 근거를 남긴다.
Lighthouse의 방법은 실제 계약→코드→검사 연결을 추적하되 전용 계약 계층·훅·검사 수를 그대로 복제하지 않는다.

## 사용 뒤 판단할 질문

- 설명을 듣지 않고 연습을 시작하고, 해설을 확인하고, 고친 답을 따로 남길 수 있는가.
- 중단한 뒤 무엇을 하던 중이었고 무엇이 저장됐는지 알아볼 수 있는가.
- 장면·입력의 배치와 글자·색·간격이 읽고 쓰기에 편한가.

실제 응답은 아직 없다. 위 질문은 강PD가 수행한 뒤에만 결과를 적는다.

## 실행 결과와 남은 일

2026-10-26 로컬 정적 서버에서 Playwright Chromium으로 위 경로를 실행했다. 검사용 문장은 임시 브라우저
컨텍스트에서만 입력했으며 학습 기록으로 옮기지 않았다. 스크린샷은 `design/screenshots/`에 빈 수행 상태로 남겼다.
PC·모바일 화면을 직접 보았고 장면·입력·주 행동의 배치를 확인했다. 이는 강PD의 사용성 평가가 아니다.

독립 리뷰에서 자료 열람 뒤 작성 위치를 잃는 문제를 발견해 스크롤·입력 초점·커서 복원을 추가했고 세 폭에서 확인했다.
본문 건너뛰기의 경로 이동과 저장 실패 안내가 입력에서 멀리 있는 문제도 수정했다.
실제 서버 저장·인증·AI 질답·다른 기기 복원과 강PD의 이해·편리함은 여전히 미확인이다.
기존 운영 앱의 경로·API는 바꾸지 않았으며 실제 디자인 교체는 다음 구현에서 이어 간다.
