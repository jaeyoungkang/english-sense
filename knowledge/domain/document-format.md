# 도메인 모델: 문서 형식

문서의 내용을 문단, 표, 목록, 번호 목록, 제목, 코드 블록 가운데 어디에 담을지 정할 때 쓴다. 문장을 어떻게 쓰는지는
이 모델이 맡지 않는다.

## 개념

| 개념 | 뜻 |
| --- | --- |
| 형식(format) | 내용을 담는 꼴. 문단, 표, 목록, 번호 목록, 제목, 코드 블록이다 |
| 문단(paragraph) | 중심 생각 하나를 문장으로 이어 쓴 묶음 |
| 표(table) | 항목들을 같은 축으로 늘어놓은 꼴 |
| 목록(list) | 나란한 항목을 늘어놓은 꼴. 번호 목록(numbered list)은 순서가 있는 항목을 늘어놓는다 |
| 제목(heading) | 문서의 한 부분이 무엇을 담는지 알리는 말 |

그 밖의 개념은 `knowledge/concepts.md`를 따른다.

## 관계

1. 독자는 문장보다 꼴을 먼저 본다. 표는 견줄 축이 있다고, 목록은 항목이 나란하다고, 번호는 순서가 있다고 알린다. 꼴이
   내용과 맞지 않으면 독자는 내용에 없는 비교나 순서를 읽는다.
2. 생각 사이의 까닭, 조건, 대조는 문장으로 이어야 드러난다. 목록으로 쪼개면 항목은 잘 보이지만 항목 사이의 관계가 사라진다.
3. 독자는 문서를 처음부터 읽기보다 필요한 곳을 찾아 읽는다. 제목이 내용을 말하지 않으면 본문을 다 읽어야 찾는다.
4. 코드는 무엇을 하려는지와 무엇을 전제하는지를 스스로 말하지 않고, 그 결과도 해석 없이는 뜻이 서지 않을 때가 많다.

## 규칙

1. 한 문단은 중심 생각 하나를 발전시킨다. (관계 2)
2. 비교에는 표, 나란한 항목에는 목록, 절차에는 번호를 쓴다. 항목 수만으로 산문과 목록을 정하지 않는다. (관계 1, 2)
3. 제목은 내용을 찾기 쉽게 붙인다. (관계 3)
4. 코드 앞에는 목적과 전제를, 뒤에는 필요한 결과 해석을 적는다. (관계 4)

## 한계와 출처

- 규칙은 이오덕 자료에서 나온 것이 아니라 문서를 다루며 익힌 실무 지침이다. 2026-10-24 korean-prose 스킬 본문에서 한국어
  작문법 모델로 옮겼고(project-base #12), 2026-10-25 그 모델의 대상이 아니어서 이 모델로 뗐다(project-base #13). 규칙의
  뜻은 바꾸지 않았다.
- 관계는 떼어 내며 규칙의 까닭을 정리자가 짠 가설이다. 바깥 자료로 확인하지 않았다. (잠정)
- Markdown으로 쓰는 한국어 문서에서만 써 봤다.
